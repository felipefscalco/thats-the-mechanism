# AGENTS.md — That's the Mechanism

This is the **canonical** instruction set for any coding agent or LLM working in this repository (Claude, Gemini, Cursor, Copilot, Codex, or anything else). `CLAUDE.md`, `GEMINI.md`, `.cursor/rules/`, and `.github/copilot-instructions.md` only point here.

Read this file, `docs/STYLE_BRIEF.md`, `docs/STYLE_RULES.md`, and `docs/active_rules_prompt.txt` (generated by `scripts/lessons.py`) before writing a script or touching Remotion code. Stage-specific procedures live in `skills/<name>/SKILL.md`.

## What this repo is

A local pipeline that turns a fact-checked script into a 35–55 second, 1080×1920 explainer Short with a cloned-or-synthetic voice, word-level captions, original Remotion animation, and licensed SFX. The channel is **That's the Mechanism**: one everyday thing, opened up.

It is **not** a publisher. It does not call the YouTube, Instagram, or TikTok upload APIs.

## Enforcement hierarchy: code over prose

Every lesson and critic rule must be enforced. Prefer an implementation that cannot be ignored, in this order:

1. **Gate** — an automated check (typically in `scripts/qa.py`, or a sibling such as `scripts/facts.py` / `scripts/contrast.py`) that **blocks the render** when it fails.
2. **Component** — a Remotion primitive or layout in `remotion/src/brand/` that makes the error impossible (for example `Lane` / `LabeledBox` in `Kit.tsx`, which guarantee icon/label clearance, or `LoopEnd` in `EpisodeShell.tsx`, which locks the last frame to the frame-0 hook).
3. **Prose** — only for subjective craft that cannot be measured or locked in structure (wow moment, script tone, conceptual framing). Those belong in `docs/STYLE_RULES.md`, not as a substitute for a gate or a component.

New critic rules must declare their enforcement class (`gate`, `component`, or `prose`) in `general_rules`. A prose rule that becomes measurable must be promoted to a gate. `scripts/lessons.py` merges critic `general_rules` into `docs/STYLE_RULES.md` and writes the active prose prompt to `docs/active_rules_prompt.txt`.

## Hard rules

1. **Do not publish, schedule, or upload** a video, description, or comment anywhere. Stop at a reviewed MP4 + `metadata.md` entry and wait for a human.
2. **Human approval at four gates:** the episode angle, the finished script (with sources), the style frames for any new look (`style_frames/`), and the final video. Do not skip a gate.
3. **Fact-check every factual claim with at least two independent sources.** Record them in `episodes/<slug>/sources.json`. If a claim cannot be sourced, cut it or flag it — never invent a number.
4. **On-screen text is ≥ 30 px** on the 1080-wide stage (`<Label>` enforces this). Max two text levels on the stage; captions are a separate track.
5. **Respect safe zones.** Content lives in y 290–1190. Captions 1222–1440. Chapter deck 1462–1552. Nothing important below y 1560 or in the right-hand platform column (x > 900 and y > 900).
6. **No cross-fades between sections.** Transitions are world moves: push-through, whip, whipUp, or cut+punch.
7. **Do not add media you cannot license.** Use the Kenney CC0 packs, the original synth cues, the papercut-explainer MIT cues, `assets/library/` (own SVG/Lottie, Lucide ISC, Tabler MIT), or new assets with a recorded license in `sfx/CREDITS.csv` / `LICENSES.md`. Real photos must be public domain or CC0, verified at the source with `scripts/photos.py` and logged in `assets/photos/CREDITS.csv` (`skills/licensed-photos`). Do not pull random YouTube audio, thumbnails or copyrighted clips.
8. **Do not commit secrets, tokens, `.env` files, model binaries, or rendered MP4s.** See `.gitignore`. API keys (e.g. `GEMINI_API_KEY`) are read from the environment only; never print them or put them in a URL, log or file.
9. **Do not treat `IceDemo` as a shippable episode.** It is a template smoke test.
10. **Prefer editing the brand kit over forking it.** Shared look lives in `remotion/src/brand/`. Episode files only provide the subject and shot list.

## Pipeline stages

|---|---|---|---|
| 1 | Scaffold | `skills/new-episode` | `scripts/new-episode.sh <slug> <CompId> <pillar> "HOOK" "SOURCE"` |
| 2 | Script + fact-check | `skills/script-and-factcheck` | `episodes/<slug>/script.txt`, `brief.md`, `sources.json`, `shots.md` |
| 3 | Voice | `skills/voice` | Kokoro TTS + loudnorm −14 LUFS → `narration.wav` |

| 5 | Animate | `skills/animate-remotion` | `remotion/src/episodes/<CompId>.tsx` from `templates/Episode.tsx.tmpl` |
| 6 | SFX + mix | `skills/sfx-mix` | `scripts/mix_one.sh` + `<Sfx cue>` in the composition |
| 5a | Style frames (new look only) | `skills/animate-remotion` | `remotion/style_frames.mjs` → `style_frames/` contact sheets → **owner picks a look** |
| 5b | Real-photo proof | `skills/licensed-photos` | `scripts/photos.py search/pick` → `remotion/public/photos/`, `assets/photos/CREDITS.csv`, `episodes/<slug>/photo_credits.md`; shown with `<ProofCard>` |
| 7 | Render + QA loop | `skills/qa-loop` | `scripts/build-episode.sh` then `SUF=v4 MASTER=1 scripts/iterate.sh <N> <Ids…>` |
| 7b | Independent critic | `skills/critic` | `scripts/critic.py <Id>` (needs `GEMINI_API_KEY`) → `qa/<Id>/<SUF>/critic.{json,md}` |
| 8 | Package metadata | `skills/package-metadata` | Title, description (with photo credits), hashtags, pinned comment, AI-label notes |

`scripts/build-episode.sh <slug> <CompId>` runs stages 3–7 once. After you change animation or shots, `scripts/iterate.sh <N> <CompId>` re-lints, re-renders and re-QAs.

## Setup

```bash
scripts/setup.sh --fast    # Node deps + Python venv (typecheck only)
scripts/setup.sh           # also Kokoro models + whisper.cpp + small.en
(cd remotion && npx tsc --noEmit -p .)
```

Python must be `.venv-tts/bin/python` for TTS and captions (kokoro-onnx). The shell scripts already use that interpreter.

## Style brief (summary)

Full text: `docs/STYLE_BRIEF.md`. Non-negotiables:

- Editorial engineering-diagram look, not cartoon 3D, not a slideshow.
- Palette: ink `#0D0E12`, paper `#F3EFE6`, accent amber `#FFB020`, one pillar colour (tech `#4CC9F0`, engineering `#7BD389`, physics `#9B8CFF`, philosophy `#FF7AB6`). Red and green are reserved for fail / success.
- Type: Space Grotesk (display), Inter (captions), JetBrains Mono (data).
- Hook: the subject is on screen and moving at **0.3 s**; a visible change by 1.0 s. No title card first.
- Something happens on the stage at least every **2 s** (lint also requires a beat every ≤ 3 s).
- Structure: hook → tension → 2–3 mechanism beats → turn → card **"THAT'S THE MECHANISM."** → a 6–10 word callback → exact loop back to frame 0.
- The spoken script must contain the line `That's the mechanism.`
- One special moment per episode (a real proof on screen — e.g. a QR that actually scans).
- Voice at −14 LUFS; SFX 10–16 dB under the voice (never closer than 8 dB); whoosh on every world move; signature sting on the catchphrase.

## Acceptance checklist

An episode is done only when **every automated check in `docs/ACCEPTANCE.md` PASSes** (A1–A12: format, loudness, SFX under voice, SFX density 1.2–1.5/s, motion, hook, frame-0 brightness, loop, WCAG label contrast, end-card hold, label size, shot lint) and a visual review of the transition/grid sheets finds no style failure (slideshow, empty half, camera into UI, clipped labels, triple push, late hook, dead air, SFX spam). Automated runner: `scripts/qa.py` → `qa/<Id>/report_it<N>.json`.

Do not call a video “acceptable” from metrics alone. Look at `qa/<Id>/grid_it<N>.png` and `transitions_it<N>.png`.

## Round-5 rules
- Never voice a script before `scripts/facts.py check <slug>` passes; `tts.py` enforces this.
- Respect `pipeline.config.json` gates. Record every human decision with `scripts/gates.py approve <slug> <gate> --changes "..." | --no-changes`. Use env overrides (`GATE_MODE_X=auto`) only when asked; they are logged.
- The builder is not the judge: ship only if the pairwise critic prefers the new render over the last approved one. Budget Gemini free-tier calls (20/model/day, L-22).
- Do not edit `remotion/src` while a QA batch is running (L-24). After adding a camera punch, check edge labels stay at x ≤ 900.

## Working agreements

- Keep changes reviewable: one episode or one kit fix per change set when you can.
- After animation edits run `(cd remotion && npx tsc --noEmit -p .)` before rendering.
- Record timing with `scripts/metrics.py` (the build/iterate scripts already wrap stages).
- If you add a tool or sound, document the license.
- Shipped since round 3: ffmpeg-normalize mastering (`scripts/master.sh`), Lucide/Tabler icons, the WCAG contrast probe, licensed photos, the Gemini critic. Still **not** in this tree: a voice clone, Qwen3-TTS. Do not describe those as shipping.
- Shared-box hygiene: write scratch files inside the project folder, never generic `/tmp` names (L-17).

## Review memory (mandatory)
- Before any work on an episode or the kit, read `docs/LESSONS.md` and `docs/STYLE_RULES.md`, and apply every active prose rule in `docs/active_rules_prompt.txt`.
- After every review or QA iteration, append each finding to `docs/LESSONS.md` (format in that file) and each non-bug idea to `docs/BACKLOG.md`. A repeated finding is a regression: reopen the entry and add an automated check.
- Commit the log updates together with the fix.
